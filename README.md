# Агент, який бронює столик (Telegram)

Тестове завдання на позицію AI Builder. Агент сам починає розмову в Telegram з менеджером лондонського ресторану, ввічливо англійською просить столик на двох на 17:00 сьогодні, реагує на відповіді, підтверджує бронь і повторює її деталі.

## Статус

- Агент пройшов повну розмову з менеджером `@vlad_dev_7`: сам почав розмову, запросив столик на 17:00, отримав відповідь, що 17:00 зайнято, а вільні 17:30 та 18:00, і прохання назвати ім'я. Агент не вигадував відповідей, а запитав мене (`ask_owner`). Я обрав 17:30 та ім'я. Далі менеджер перевіряв із кухнею, потім підтвердив, і агент повторив бронь: час, дату, кількість людей, ресторан та ім'я.
- **Відома прогалина, виявлена в реальній розмові:** після підтвердження менеджер написав, що клієнт нібито зателефонував і скасував бронь. Агент цього повідомлення **не побачив**, бо одразу після стану `confirmed` програма відключалась. Повідомлення є на скриншоті переписки, але його немає в `decision-log.jsonl`. Опис проблеми й запропоноване виправлення нижче в розділі «Обмеження».
- Голосові повідомлення (завдання із зірочкою) **не реалізовані**.

## Як це працює

```
Telegram-акаунт (GramJS, userbot)
        │ нове повідомлення від менеджера
        ▼
  debounce 3 с (збирає кілька повідомлень підряд в одне)
        │
        ▼
  Gemini: системний промпт + історія розмови
        │  повертає JSON: { reply, state, ask_owner, log_line }
        ├─► reply        → надсилається менеджеру (з імітацією набору тексту)
        ├─► ask_owner    → питання мені в терміналі; моя відповідь іде в наступний запит
        └─► log_line     → рядок у decision-log.jsonl
```

Ключові рішення:

- **Userbot, а не звичайний бот.** Звичайний Telegram-бот не може першим написати людині, яка його не запускала, а за умовами менеджер не пише першим. Тому агент працює через MTProto (бібліотека GramJS) від імені звичайного акаунта.
- **Агент не вигадує дані.** Він знає лише факти з `CONFIG` (ресторан, дата, час, кількість людей). Якщо менеджер питає про щось інше (ім'я, телефон, алергії) або пропонує інший час, агент ставить `ask_owner`, зупиняється й питає мене.
- **Структурована відповідь.** Модель повертає JSON, який перевіряється через `zod`. При тимчасових помилках (503, 429) запит повторюється, а потім перемикається на запасну модель.
- **Завершення.** Коли стан `confirmed` або `failed`, агент завершує роботу (див. обмеження).

## Запуск

Потрібні Node.js і Telegram-акаунт.

```bash
npm install
cp .env.example .env     # заповни значення
npx tsx login.ts         # один раз: номер, код з Telegram, пароль 2FA → вставити рядок у TG_SESSION
npx tsx agent-telegram.ts
```

Змінні `.env`:

```dotenv
GEMINI_API_KEY=      # ключ з Google AI Studio (безкоштовний рівень)
MODEL=               # основна модель Gemini
FALLBACK_MODEL=      # запасна модель на випадок 503
TG_API_ID=           # з my.telegram.org
TG_API_HASH=         # з my.telegram.org
TG_SESSION=          # рядок з login.ts
TARGET_USERNAME=     # @username менеджера
```

Ресторан, час і кількість людей задаються в `CONFIG` на початку `agent-telegram.ts`. Дата береться автоматично за часовим поясом `Europe/London`. Перед відправкою першого повідомлення агент просить підтвердження в терміналі (`y/n`).

## Лог рішень

Файл `decision-log.jsonl`: один JSON-рядок на кожну подію (повідомлення менеджера, повідомлення агента, питання власнику). Поле `log_line` пише сам агент: що він зрозумів і що вирішив.

## Обмеження та відомі проблеми

- **Завершення після `confirmed` (виявлено в реальній розмові).** Програма виходить одразу після підтвердження, тому не бачить подальших змін від менеджера, зокрема повідомлення про нібито скасування від клієнта. Правильна поведінка: не приймати таке на віру (агент не має даних про скасування), спитати мене через `ask_owner`, а якщо я скажу, що не скасовував, ввічливо попросити зберегти столик. **Запропоноване виправлення** (не застосоване): після `confirmed` продовжувати слухати чат ще кілька хвилин і додати в системний промпт правила обробки скасувань.
- Немає нагадування, якщо менеджер довго мовчить.
- Історія розмови зберігається лише в пам'яті: після перезапуску агент починає з нуля.
- Голосові повідомлення не розпізнаються й не надсилаються. Якщо менеджер надсилає голосове, агент просить написати текстом.
- Агент працює від імені мого особистого акаунта (окремого номера для нього не було). Менеджер бачить моє ім'я та фото. Чистіше рішення: окремий акаунт для агента.
- Використано безкоштовний рівень Gemini: бувають 503 і зміни доступних моделей.

## Безпека

`.env` і рядок сесії Telegram дають повний доступ до акаунта й API, тому вони в `.gitignore` і не комітяться.
